<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI / local → Firebase Hosting | Firebase CLI deploy authenticates with Google OAuth; API key not needed for deploy |
| Public internet → deployed Hosting URL | URL is public; app is served to any visitor; Firestore rules enforce auth at data layer |
| Public internet → Firestore REST API | Unauthenticated REST requests must be denied by security rules |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Elevation of Privilege | Unauthenticated Firestore REST read | mitigate | Firestore security rules deployed in Task 1 require `request.auth != null`; Test 4 in checkpoint verifies this returns HTTP 403 |
| T-03-02 | Information Disclosure | Firebase Hosting URL guessability | accept | URL obscurity (long random subdomain) is the access control for MVP — explicitly scoped per PROJECT.md "Out of Scope: Passcode/PIN gate UI". Two known users in a private family context. |
| T-03-03 | Denial of Service | Firebase free tier (Spark) limits | accept | Spark tier limits: 50K reads/day, 20K writes/day, 1GB storage. A two-person family tracker will never approach these limits. No billing protection needed. |
| T-03-04 | Tampering | Malicious firebase.json rewrite rules | accept | firebase.json is committed to git; changes are auditable. The rewrite rule `**` → `index.html` is standard SPA config with no attack surface beyond serving the app. |
| T-03-SC | Tampering | npm/firebase-tools used in deploy | mitigate | firebase-tools is Google-maintained; installed as dev dependency in Plan 01 at a pinned version. No new installs in this plan. |
</threat_model>
