    This task runs inside the existing repo root `/Users/michael/Coding/madgy-ins-and-outs`.

    Step 1 — Scaffold Vite app into current directory:
    Run `npm create vite@latest . -- --template react-ts` (the `.` targets the current dir). Accept the overwrite prompt.

    Step 2 — Install all dependencies:
    Run `npm install` to install base Vite/React deps.
    Then run `npm install firebase` to add the Firebase SDK.
    Then run `npm install -D @tailwindcss/vite` to add Tailwind via the Vite plugin (per D-11 — do NOT use the postcss-based tailwindcss setup; the `@tailwindcss/vite` plugin is the correct approach for Vite projects with Tailwind v4).

    Step 3 — Configure Tailwind in vite.config.ts:
    Import `tailwindcss` from `@tailwindcss/vite` and add it to the `plugins` array:
    ```
    import tailwindcss from '@tailwindcss/vite'
    // ...
    plugins: [react(), tailwindcss()]
    ```

    Step 4 — Add Tailwind import to src/index.css:
    Replace the entire content of src/index.css with:
    ```
    @import "tailwindcss";
    ```
    (This is the Tailwind v4 / @tailwindcss/vite import syntax — not `@tailwind base/components/utilities`.)

    Step 5 — Create src/lib/firebase.ts:
    Create the file with the following structure. The config values come exclusively from `import.meta.env.VITE_FIREBASE_*` env vars (per D-03 — never hardcode values):
    - Import `initializeApp` from `firebase/app`
    - Import `getAuth` from `firebase/auth`
    - Import `getFirestore` from `firebase/firestore`
    - Build a `firebaseConfig` object reading:
      - `apiKey: import.meta.env.VITE_FIREBASE_API_KEY`
      - `authDomain: import.meta.env.VITE_FIREBASE_AUTH_DOMAIN`
      - `projectId: import.meta.env.VITE_FIREBASE_PROJECT_ID`
      - `storageBucket: import.meta.env.VITE_FIREBASE_STORAGE_BUCKET`
      - `messagingSenderId: import.meta.env.VITE_FIREBASE_MESSAGING_SENDER_ID`
      - `appId: import.meta.env.VITE_FIREBASE_APP_ID`
    - Call `initializeApp(firebaseConfig)` and store as `app`
    - Export `app`, `auth` (from `getAuth(app)`), and `db` (from `getFirestore(app)`)

    Step 6 — Create .env.example in the repo root:
    ```
    VITE_FIREBASE_API_KEY=your-api-key-here
    VITE_FIREBASE_AUTH_DOMAIN=your-project-id.firebaseapp.com
    VITE_FIREBASE_PROJECT_ID=your-project-id
    VITE_FIREBASE_STORAGE_BUCKET=your-project-id.firebasestorage.app
    VITE_FIREBASE_MESSAGING_SENDER_ID=your-sender-id
    VITE_FIREBASE_APP_ID=your-app-id
    ```

    Step 7 — Create .env in the repo root with the real values from the checkpoint. Fill in the actual values provided by the user in Task 1.

    Step 8 — Update .gitignore to ensure `.env` is excluded (the Vite template already includes it, but verify the line `*.local` or `.env` exists; add `.env` explicitly if not present).

    Step 9 — Strip the Vite template boilerplate from src/App.tsx. Replace it with a minimal scaffold:

    This is intentionally thin — Plan 02 adds auth + components.

    Step 1 — Install Firebase CLI if not present:
    Run `npm install -D firebase-tools` to add it as a dev dependency (so `npx firebase` works without a global install).

    Step 2 — Create firebase.json in the repo root with this exact structure:
    ```json
    {
      "hosting": {
        "public": "dist",
        "ignore": ["firebase.json", "**/.*", "**/node_modules/**"],
        "rewrites": [
          {
            "source": "**",
            "destination": "/index.html"
          }
        ]
      }
    }
    ```
    The `rewrites` rule ensures React Router (if added later) works and that direct URL access returns index.html.

    Step 3 — Create .firebaserc in the repo root. Use the Project ID provided by the user in Task 1:
    ```json
    {
      "projects": {
        "default": "YOUR_PROJECT_ID"
      }
    }
    ```

    Step 4 — Add `.firebaserc` and `firebase.json` to git staging (they should be committed). Do NOT add `.env`.
