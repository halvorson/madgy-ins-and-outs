## 2. Spacing

Scale: 8-point grid (multiples of 4px only). Inherited from Phase 2.

| Token | px | Usage |
|-------|----|-------|
| 1 | 4px | Inline label gap, tight badge spacing |
| 2 | 8px | Button internal padding (y-axis), label-to-value gap |
| 4 | 16px | Card internal padding (`p-4`), horizontal container padding (`px-4`) |
| 6 | 24px | Card-to-card gap (`gap-6`), section-to-section gap |
| 8 | 32px | Header bottom margin |

**Section header spacing (new in Phase 3):**

- Gap between section header and first card in its group: `gap-2` (8px).
- Gap between last card of one section and the section header of the next: `mt-6` (24px) — same
  as the card-to-card gap, keeping visual rhythm consistent.
- Section headers are not cards; they live outside the `gap-6` flex/grid and are applied via
  margin.

**Concrete layout:**

```
[Pills header]          ← no top margin on first section
  [Carprofen card]      ← gap-2 below header
  [Gabapentin card]     ← gap-6 between cards
  [Trazodone card]
[Activities header]     ← mt-6 from last pill card (matches card-to-card rhythm)
  [Ate card]
  [Peed card]
  [Pooped card]
```

**Touch targets:** All interactive elements maintain 44px minimum height (existing `min-h-[44px]`
pattern). Section headers are not interactive; no touch target requirement.

Exceptions: none.

## 3. Typography

Exactly 4 sizes, 2 weights. Phase 2 established 3 sizes; Phase 3 adds 1 size for section headers.
The 2-weight constraint is preserved (regular 400 + semibold 600).

| Role | Size | Weight | Line Height | Class |
|------|------|--------|-------------|-------|
| Page title | 20px (`text-xl`) | 600 semibold | 1.25 (`leading-tight`) | `text-xl font-semibold leading-tight` |
| Card label / Button | 14px (`text-sm`) | 600 semibold | 1.5 (`leading-relaxed`) | `text-sm font-semibold` |
| Supporting / meta text (elapsed, never) | 14px (`text-sm`) | 400 regular | 1.5 (`leading-relaxed`) | `text-sm font-normal leading-relaxed` |
| Section header | 12px (`text-xs`) | 400 regular | 1.5 (`leading-relaxed`) | `text-xs font-normal uppercase tracking-wide` |

**Section header note:** `text-xs` (12px) is the single addition to the type scale. It appears
only on the `Pills` and `Activities` labels. No other new sizes are permitted.

60/30/10 split. Inherited from Phase 2. No new colors introduced.

| Role | Color | Usage |
|------|-------|-------|

| 30% secondary surface | `white` / `gray-200` | Cards (`bg-white`, `border-gray-200`) |

| Disabled surface | `blue-600 opacity-50` | Disabled Log button |

**"just now" text color:** `gray-500` — same as all other elapsed text. No special color or
accent. The text content itself (`just now` vs `Nh Nm ago`) is the differentiator; color
consistency avoids a noisy UI.

**Accent contract:** `blue-600` is reserved exclusively for the Log button and the active identity
picker button. Section headers, elapsed time, and "Never" text use gray scale only.

## 6. Elapsed-Time Display Contract

### Format rules

| Condition | Display |
|-----------|---------|
| < 60 seconds since log | `just now` |
| >= 60 seconds since log | `Nh Nm ago` — always both units |
| No log entry exists | `Never` |

**Format examples:**
- 45 minutes elapsed → `0h 45m ago`
- 2 hours 30 minutes → `2h 30m ago`
- 14 hours exactly → `14h 0m ago`
- 27 hours → `27h 0m ago` (no day units — hours only, per D-03)
- 59 seconds → `just now`
- No prior log → `Never`

**Never-casing:** Capital N, word only. Not "Never logged", not "—", not an icon.

**just now casing:** All lowercase. Not "Just now", not "Just Now".

### Computation

- Source: `Record<string, Timestamp>` map in App state (`trackableId → latest Timestamp`).
- Built by reducing over the `onSnapshot` docs, taking the highest `timestamp` per `trackableId`.
- If `trackableId` absent from the map: display `Never`.
- Current time for elapsed calculation: `Date.now()`.
- Elapsed = `Date.now() - timestamp.toMillis()` in milliseconds.

### Auto-update

- Tick interval: 30 seconds (`setInterval`, 30000ms).
- On each tick: recompute elapsed strings from the existing last-logged map + current time.
- On each Firestore snapshot: rebuild the last-logged map (which triggers a re-render, which
  recomputes elapsed strings immediately — no wait for the next tick).
- The 30-second interval means displayed elapsed can be up to 30 seconds stale between ticks.
  This is acceptable for this use case.

### "just now" UX note

The intent is that tapping Log and immediately seeing `just now` on that card confirms the tap
registered. This transition must be fast — the elapsed text updates immediately when the snapshot
callback fires (not deferred to the next timer tick).

## 7. Component Inventory

### 7.1 Existing components (extend in Phase 3)

**`TrackableCard`**

New prop: `lastLoggedText: string`

- Value is one of: `"just now"`, `"Nh Nm ago"`, or `"Never"`.
- Formatting is computed upstream (in App or a utility function); the card receives a pre-computed
  string and renders it verbatim.
- The `<p>` that renders `&mdash;` becomes: `<p className="text-sm font-normal leading-relaxed text-gray-500 mt-1">{lastLoggedText}</p>`
- No other props change in Phase 3.

**`TrackableList`**

New behavior: split the `trackables` array by `type` field before rendering.

- Pills group: `trackables.filter(t => t.type === 'pill')` — rendered first.
- Activities group: `trackables.filter(t => t.type === 'activity')` — rendered second.
- Each group renders inside a `<section>` with a `<h2>` section header above a `<ul>`.
- Order within each group preserved from config (D-10).

Section header element:

```
<h2 className="text-xs font-normal uppercase tracking-wide text-gray-400">
  {label}
</h2>
```

Labels: `Pills` (for type `'pill'`) and `Activities` (for type `'activity'`).

**`App`**

Three additions:
1. Firestore snapshot callback: reduce docs into `Record<string, Timestamp>` state.
2. `setInterval` (30s) to trigger elapsed-time re-render.
3. Elapsed text computation: utility function `formatElapsed(timestamp: Timestamp | undefined): string`.

### 7.2 New utility (no UI)

**`formatElapsed(timestamp: Timestamp | undefined): string`**

- Input: a Firestore `Timestamp` or `undefined` (never logged).
- Output: `"just now"`, `"Nh Nm ago"`, or `"Never"`.
- Lives in `src/lib/elapsed.ts` (new file) or inline in `App.tsx` if the planner prefers brevity.
- Pure function — no side effects, easy to unit test.

### 7.3 No new components

No new React components are introduced. All Phase 3 changes are extensions of existing components
plus the utility function.

## 10. Accessibility

All Phase 2 accessibility contracts inherited:
- Native `<button>` elements only (no div click handlers).
- `disabled` attribute on disabled Log buttons (not just CSS).
- `min-h-[44px]` on all interactive elements.
- `aria-pressed` on identity picker buttons.

Phase 3 additions:
- Section `<h2>` elements provide document structure for screen readers. No `aria-label` needed —
  `Pills` and `Activities` are descriptive enough as heading text.
- Elapsed text `<p>` is already in the DOM and will be read by screen readers. No `aria-live`
  required — 30-second tick updates are not urgent enough to warrant live region announcements.
  (If the product later requires "med due" alerts, add `aria-live="polite"` at that point.)
- Color contrast: `gray-400` (#9CA3AF) on `gray-50` (#F9FAFB) is approximately 2.3:1 — below
  WCAG AA for text. This is intentional and acceptable for section headers at 12px uppercase:
  they are decorative structure labels, not content. If stricter contrast is needed, use
  `gray-500` (#6B7280) on `gray-50` (~4.6:1). Use `gray-500` if accessibility is a priority.
